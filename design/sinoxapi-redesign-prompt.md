# پرامپت کامل ریدیزاین فرانت‌اند sinoxapi.com

> این سند یک پرامپت آماده برای دادن به Claude است. هر ۱۰ بخش را به ترتیب اجرا کن.
> پالت رنگی فعلی **حفظ می‌شود** — فقط نحوه‌ی استفاده از آن حرفه‌ای می‌شود.

---

## بخش ۰ — کانتکست (این را قبل از هر کاری بخوان)

تو در حال ریدیزاین کامل فرانت‌اند سایت **Sinox API** هستی؛ یک سرویس ایرانی فروش دسترسی به API مدل‌های
هوش مصنوعی (سازگار با فرمت OpenAI و Anthropic) با پرداخت ریالی/کریپتو.

**وضعیت فنی فعلی:**

- HTML استاتیک ساده (بدون فریم‌ورک)، یک فایل `/css/style.css` سراسری (۶۱۱ خط)، یک `/js/app.js`.
- زبان: فارسی، `dir="rtl"`، فونت `Vazirmatn` از Google Fonts (وزن‌های ۳۰۰/۴۰۰/۵۰۰/۷۰۰/۹۰۰).
- صفحات عمومی: `/` ، `/docs` ، `/articles` ، `/article/:slug` ، `/health` ، `/login` ، `/register`
- صفحات خصوصی: `/dashboard` (۱۰ تب) و پنل ادمین.
- داده‌ها از این اندپوینت‌ها می‌آید:
  - `GET /api/config` → `{base_url, site_name}`
  - `GET /api/models/public` → آرایه‌ی `{model_id, display_name, provider, tier: standard|premium, billing_type: request|token}`
  - `GET /api/plans` → `{plans[], tether_rate, tether_updated_at, gates:{zarinpal, card, crypto}}`
  - `GET /api/health/system` , `GET /api/health/models` , `GET /api/articles`
- در حال حاضر **۳۱ مدل** و **۸ پکیج** برمی‌گردد.

**قانون طلایی:** ساختار داده و اندپوینت‌ها را تغییر نده. فقط لایه‌ی نمایش را بازنویسی کن.
هیچ متن فارسی‌ای را بدون دلیل حذف نکن؛ اگر متنی را بهتر می‌نویسی، لحن دوستانه و غیررسمی فعلی
(«شروع کن»، «هرچی می‌خوای») را حفظ کن.

## بخش ۱ — تشخیص مشکل و اصول ریدیزاین

### ۱-۱. چیزی که الان خراب است (این‌ها را عیناً رفع کن)

**باگ‌های واقعی CSS/مارکاپ که در بازرسی پیدا شد:**

| # | باگ | محل | نتیجه |
|---|-----|-----|--------|
| ۱ | `var(--surface)` تعریف نشده (۶ بار استفاده شده) | `articles.html` و کارت‌های مقاله | کارت مقاله پس‌زمینه ندارد، شفاف روی بک‌گراند |
| ۲ | `var(--secondary)` تعریف نشده | `.pricing-card .plan-badge` گرادیانت | بج «پرفروش» گرادیانت شکسته دارد |
| ۳ | `var(--error)` تعریف نشده | هندلر خطای مقالات | متن خطا بی‌رنگ |
| ۴ | `.plan-badge` با `right:50%; transform:translateX(50%)` | کارت قیمت | بج در RTL از گوشه‌ی کارت بیرون می‌زند، وسط نیست |
| ۵ | متن دکمه‌ی «ثبت نام» از قاب دکمه بیرون زده | نوبار، `.btn-sm` | کلیپینگ متن روی دکمه‌ی اصلی CTA |
| ۶ | `grid-3` با `auto-fill` و ۴ کارت | بخش قیمت‌گذاری | کارت چهارم تنها در ردیف بعد می‌افتد (یتیم) |
| ۷ | `provider` در API خالی است ولی UI آن را نمایش می‌دهد | گرید مدل‌ها | `model_id` جای نام سازنده نشسته: «claude-opus-5 / Claude Opus 5» تکراری |
| ۸ | کپچا در RTL به‌هم‌ریخته | `/login` و `/register` | باکس سؤال، اینپوت پاسخ و آیکن رفرش در ترتیب اشتباه |
| ۹ | `.nav-brand` با `justify-content:space-between` در کارت لاگین | `/login`, `/register` | لوگو و نام برند بی‌دلیل از هم دور افتاده‌اند |
| ۱۰ | پلن‌های تستی (`test`, `token test` با قیمت ۱ دلار) عمومی هستند | صفحه اصلی | بی‌اعتمادی و ظاهر ناتمام |

**مشکلات طراحی (چیزی که «زننده» بودن را می‌سازد):**

- **همه‌چیز یک کارت است.** ۳۱ مدل، ۸ پکیج، ۴ مرحله، ۲ بلوک کد — همه در `.card` یکسان با
  `padding:24px` و `radius:14px`. صفحه یک دیوار جعبه‌ی تکراری است بدون سلسله‌مراتب.
- **اموجی به‌جای آیکن.** `⚡` لوگو، `1️⃣2️⃣3️⃣4️⃣` مراحل، `🟦🟪` بجِ نوع پکیج، `📚📡💰🤖` منو،
  `🔄` رفرش. هیچ آیکن‌ست حرفه‌ای‌ای وجود ندارد. این تنها بزرگ‌ترین عامل ارزان به نظر رسیدن سایت است.
- **هیرو خالی و بی‌جان.** `padding:70px 20px 40px`، فقط تیتر + پاراگراف + دو دکمه، بعد ~۱۵۰px فضای مرده.
  هیچ ویژوال، دموی زنده، اسکرین‌شات، آمار یا سیگنال اعتمادی نیست.
- **صفحه‌ی موبایل ۱۰۸۱۵ پیکسل ارتفاع دارد.** چون ۳۱ کارت مدل تمام‌عرض روی هم چیده می‌شوند.
  کاربر موبایل هرگز به بخش قیمت نمی‌رسد.
- **بلوک کد بدون هایلایت سینتکس، بدون دکمه‌ی کپی، بدون تب زبان،** با فونت `Courier New`
  و رنگ متن `#9d9dc9` روی `--bg2` (کنتراست پایین).
- **فوتر یک خط است:** «© 2026 Sinox API». نه لینکی، نه قوانینی، نه راه ارتباطی، نه نقشه‌ی سایت.
- **صفحه‌ی `/docs` نامتوازن است:** سایدبار سمت راست، محتوا حداکثر ~۷۲۰px، و ~۴۶۰px ستون خالی
  سمت چپ صفحه در دسکتاپ ۱۴۴۰px.
- **صفحه‌ی `/health` صفر اطلاعات دارد:** ۳۱ کارت که همه‌شان فقط می‌گویند «فعال». نه نمودار آپ‌تایم،
  نه تاریخچه‌ی ۹۰ روز، نه لتنسی، نه اینسیدنت لاگ.
- **صفحات ورود/ثبت‌نام یک کارت شناور در خلأ هستند** — بدون نوبار، بدون لینک بازگشت، بدون پنل برند.
- **بدون موشن.** تنها ترنزیشن‌ها `transform:translateY(-1px)` روی هاور دکمه است. هیچ اسکرول-ریویل،
  هیچ استگر، هیچ استیت لودینگ اسکلتونی.
- **کنتراست ضعیف:** `--muted: #8a8aa8` روی `--card: #12122a` نسبت کنتراست حدود ۴.۳:۱ است و برای
  متن ۱۳px کافی نیست؛ فوتر با `#4a4a6a` روی `#07070f` زیر ۳:۱ است.

### ۱-۲. اصول حاکم بر ریدیزاین

۱. **از «دارک تم پیش‌فرض» به «دارک تم طراحی‌شده».** عمق با لایه‌بندی سطوح ساخته می‌شود، نه با
   یک رنگ کارت واحد. سه سطح ارتفاع تعریف کن (elevation 0/1/2) و از هرکدام معنادار استفاده کن.
۲. **کمتر ولی بهتر.** به‌جای ۳۱ کارت مساوی، ۶ مدل شاخص + یک جدول/آکاردئون قابل جست‌وجو برای بقیه.
۳. **هر بخش یک شکل بصری متفاوت داشته باشد** (گرید / تایم‌لاین / تب / جدول / اسپلیت)، نه اینکه
   همه گرید کارت باشند.
۴. **آیکن‌ها SVG اینلاین باشند، اموجی نه.** یک آیکن‌ست یکدست (استروک ۱.۵px، ۲۴px، `currentColor`).
۵. **دسترس‌پذیری قابل مذاکره نیست:** WCAG AA، فوکوس‌رینگ مرئی، `prefers-reduced-motion`.
۶. **موبایل‌فرست.** هیچ صفحه‌ای در موبایل نباید بیش از ~۶۰۰۰px ارتفاع داشته باشد.

### ۲-۳. تایپوگرافی

فونت `Vazirmatn` می‌ماند اما باید **لوکال هاست شود** (`woff2` با `font-display:swap`) — الان از
Google Fonts می‌آید که در ایران غیرقابل‌اتکاست و باعث FOIT می‌شود. یک فونت مونواسپیس هم اضافه کن
(`JetBrains Mono` یا `IBM Plex Mono`) و `Courier New` را کاملاً حذف کن.

مقیاس تایپ (کلمپ‌شده برای ریسپانسیو بودن):

```css
--fs-display: clamp(34px, 5.2vw, 60px);  /* تیتر هیرو — الان ثابت 42px است */
--fs-h1:      clamp(28px, 3.6vw, 40px);
--fs-h2:      clamp(22px, 2.6vw, 30px);  /* تیتر بخش — الان 26px */
--fs-h3:      clamp(17px, 1.6vw, 20px);
--fs-body:    16px;   /* الان 14-15px است؛ برای فارسی کوچک است */
--fs-sm:      14px;
--fs-xs:      12.5px;
--lh-tight: 1.25;  --lh-body: 1.8;  /* فارسی به line-height بلندتر نیاز دارد */
--ls-fa: -0.01em;  /* فاصله‌ی حروف کمی منفی برای وزیرمتن */
```

قواعد:
- تیتر هیرو `font-weight:900` می‌ماند اما گرادیانت متن فقط روی **بخشی** از تیتر اعمال شود، نه کل آن
  (کل تیتر گرادیانتی = افت خوانایی و ظاهر تمپلیتی).
- اعداد لاتین در متن فارسی باید با `font-feature-settings` و کلاس `.num` جدا شوند تا
  قیمت‌ها (`$17`) و اعداد فارسی (`۳٬۱۷۶٬۴۱۶ تومان`) هم‌تراز رندر شوند.
- هرگز بیش از ۳ وزن در یک صفحه.

### ۲-۴. اجزای پایه‌ای که باید بازنویسی شوند

- `.btn` → واریانت‌ها: `primary` (گرادیانت برند)، `secondary` (سطح ارتفاع‌دار)، `ghost`،
  `danger`، `success`. اندازه‌ها: `sm` (۳۲px ارتفاع)، `md` (۴۰px)، `lg` (۴۸px).
  **حتماً `line-height:1` و `white-space:nowrap` بگذار تا باگ کلیپینگ «ثبت نام» حل شود.**
  هر دکمه باید حالت `:hover`، `:active`، `:focus-visible`، `:disabled` و `.is-loading` (اسپینر) داشته باشد.
- `.card` → واریانت‌های `flat` / `raised` / `interactive` / `gradient-border`.
  حاشیه‌ی گرادیانتی را با تکنیک `mask-composite` یا `::before` بساز، نه با `border-image`.
- `.badge` → همان ۵ رنگ فعلی، اما با آیکن SVG اختیاری و ارتفاع ثابت ۲۲px.
- `.input` → ارتفاع ۴۴px، لیبل شناور یا لیبل بالا، متن خطای زیر فیلد، آیکن پیشوند/پسوند،
  حالت `aria-invalid`.
- `.skeleton` → شیمر برای همه‌ی محتوایی که با `fetch` می‌آید (مدل‌ها، پکیج‌ها، مقالات، هلث).
  الان صفحه با گرید خالی لود می‌شود و بعد ناگهان پر می‌شود.
- `.toast` → موقعیت فعلی (`bottom:24px; left:50%`) در RTL خوب است، اما باید صف پشتیبانی کند،
  آیکن داشته باشد، و `role="status"` بگیرد.
- `.tooltip`، `.tabs`، `.segmented-control`، `.accordion`، `.copy-button` را از صفر بساز
  (هیچ‌کدام الان وجود ندارند و در بخش‌های بعدی لازم می‌شوند).

### ۲-۵. پس‌زمینه

`.stars` فعلی سه `radial-gradient` ثابت است و اسمش با کارش نمی‌خواند. جایگزینش کن با:
- یک لایه‌ی گرادیانت مش (همان سه رنگ `--primary`/`--cyan`/`--primary2` با آلفای ۰.۰۵–۰.۰۸)
- یک لایه‌ی نویز ظریف (`data:` SVG با `feTurbulence`، اوپاسیتی ۰.۰۲۵) تا بندینگ گرادیانت را بشکند
- یک الگوی گرید نقطه‌ای/خطی بسیار کم‌رنگ فقط پشت هیرو، با ماسک محوشونده
- زیر `prefers-reduced-motion` هیچ‌کدام نباید انیمیت شوند

## بخش ۳ — هدر، ناوبری و فوتر

### ۳-۱. هدر دسکتاپ

وضعیت فعلی: `padding:16px 28px`، `background:rgba(13,13,26,.85)`، `backdrop-filter:blur(12px)`،
sticky، لوگوی `⚡` در مربع گرادیانتی ۳۴px، ۶ لینک متنی + ۲ دکمه.

تغییرات لازم:
- **لوگو**: مربع اموجی را با یک **لوگومارک SVG** جایگزین کن — یک مونوگرام «S» یا یک نماد
  جریان/اتصال داده، در گرادیانت `--grad-accent`. ۳۶×۳۶، شعاع ۱۰px. کنارش وردمارک «Sinox API»
  با وزن ۸۰۰. لوگو باید در SVG اینلاین باشد تا با تم هماهنگ شود.
- **ارتفاع ثابت ۶۸px** (`--nav-h`) و `align-items:center`؛ `flex-wrap:wrap` را بردار
  (الان در عرض‌های میانی نوار به دو خط می‌شکند).
- **حالت اسکرول**: در `scrollY > 8` کلاس `.is-scrolled` بگذار که `background` را به
  `rgba(10,10,22,.92)`، `blur` را به ۱۶px و `border-bottom` را پررنگ‌تر کند + `--shadow-2`.
- **لینک فعال**: صفحه‌ی جاری باید `aria-current="page"` و یک زیرخط گرادیانتی ۲px بگیرد
  (الان هیچ نشانه‌ای از صفحه‌ی فعلی نیست).
- **هاور لینک**: انیمیشن زیرخط از راست به چپ (جهت RTL)، `--dur-fast`.
- **دراپ‌داون «مدل‌ها»**: به‌جای لینک لنگرگاهی، یک پنل کوچک با سه ستون
  (مدل‌های ریکوستی / توکنی / لینک به صفحه‌ی وضعیت). با کیبورد کامل قابل استفاده.
- **دکمه‌ها**: «ورود» → `ghost sm`؛ «ثبت نام» → `primary sm` با آیکن فلش. مشکل بیرون‌زدگی متن
  را با `line-height:1` + `padding:0 14px` + `height:34px` حل کن.
- حالت لاگین‌این (اسکریپت `initAuthNav` فعلی) باید به یک **آواتار + منوی کاربر** تبدیل شود،
  نه فقط عوض شدن متن دکمه به «📊 داشبورد». منو شامل: داشبورد، کلیدهای API، اشتراک‌ها، خروج.

### ۳-۲. ناوبری موبایل

فعلی: یک `☰` که `.nav-mobile-menu` را با `display:flex` باز می‌کند — بدون انیمیشن، بدون قفل اسکرول.

- به یک **درور تمام‌ارتفاع از سمت راست** (RTL) تبدیلش کن با `transform:translateX(100%) → 0`
  و ترنزیشن `--dur` با `--ease-out`.
- بک‌دراپ تیره‌ی بلوردار، بستن با کلیک بیرون / `Esc` / سوایپ.
- `overflow:hidden` روی `body` هنگام باز بودن + تله‌ی فوکوس + `aria-expanded` روی دکمه.
- آیکن همبرگر به «ضربدر» مورف شود (دو خط SVG که می‌چرخند).
- اموجی‌های کنار آیتم‌ها (`🏠💰🤖📚📝📡`) را با آیکن SVG عوض کن.
- دو دکمه‌ی «ورود/ثبت نام» ته درور تمام‌عرض و چسبیده به پایین درور.

### ۳-۳. دکمه‌ی شناور پشتیبانی

الان: `.fab-support` تلگرام، `bottom:22px; inset-inline-end:22px`، گرادیانت آبی تلگرام
`#2AABEE → #229ED9`. **این با پالت برند نمی‌خواند و روی محتوا می‌افتد.**

- رنگش را به `--grad-brand` تغییر بده و آیکن تلگرام را داخلش نگه دار.
- در دسکتاپ بعد از ۴۰۰px اسکرول ظاهر شود (نه از ابتدا).
- در موبایل به `52px` دایره‌ای می‌شود که درست است، اما `bottom` را به `88px` ببر تا با
  نوار پایین مرورگرهای موبایل تداخل نکند.
- به یک **لانچر کوچک** ارتقایش بده: کلیک → پنلی با «پشتیبانی تلگرام»، «مستندات»، «وضعیت سرویس».

### ۳-۴. فوتر

فعلی: یک `<div>` با متن «© 2026 Sinox API — همه حقوق محفوظ است»، `color:#4a4a6a` (کنتراست زیر AA).
صفحه‌ی `/articles` اصلاً فوتر ندارد.

## بخش ۴ — صفحه اصلی: هیرو

### وضعیت فعلی

```html
<section class="hero">   <!-- padding:70px 20px 40px; text-align:center -->
  <h1>سرویس API هوش مصنوعی</h1>       <!-- 42px, 900, گرادیانت روی کل متن -->

  <a class="btn btn-ghost">مشاهده قیمت‌ها</a>
</section>
```
نتیجه: در ویوپورت ۱۴۴۰×۹۰۰ حدود ۱۵۰px فضای کاملاً خالی زیر دکمه‌ها می‌ماند و بخش بعدی
تازه از ~۵۰۰px شروع می‌شود. هیچ اثبات اجتماعی، آماری یا ویژوالی وجود ندارد.

### طراحی جدید — چیدمان دو ستونی نامتقارن (۵۵/۴۵) در دسکتاپ، تک‌ستونی در موبایل

**ستون راست (محتوا، در RTL اول می‌آید):**

1. **ایبرو / بج اعلان** — چیپ کوچک `--r-full` با حاشیه‌ی گرادیانتی:
   «⟡ سازگار کامل با OpenAI و Anthropic» یا «جدید: Claude Opus 5 اضافه شد».
   قابل کلیک به `/docs`. نقطه‌ی پالسی سبز در ابتدایش.
2. **تیتر اصلی** — `--fs-display`، وزن ۹۰۰، `line-height:1.2`. متن پیشنهادی:
   «دسترسی به **بهترین مدل‌های هوش مصنوعی دنیا**، از ایران.»
   فقط عبارت تأکیدی گرادیانت `--grad-text` بگیرد، بقیه `--text` بماند.
3. **زیرعنوان** — `--fs-body` (۱۶px)، `--text-muted`، `max-width:52ch`:
   «یک API ساده و سازگار با OpenAI. بدون تحریم، بدون VPN، پرداخت ریالی. کد فعلی‌ات را
   تغییر نده — فقط `base_url` را عوض کن.»
4. **ردیف CTA** — «شروع کن» (`primary lg` + آیکن فلش SVG، اموجی 🚀 حذف شود)،
   «مشاهده مستندات» (`secondary lg` + آیکن براکت کد). زیرشان یک خط ریز:
   «بدون کارت اعتباری • فعال‌سازی آنی».
5. **نوار اثبات** — ردیف افقی از ۳ عدد که از API واقعی می‌آید:
   `۳۱ مدل فعال` (از `/api/models/public`) · `۹۹.۹٪ آپ‌تایم` · `< ۲ ثانیه میانگین پاسخ`
   (از `/api/health/system`). با شمارنده‌ی انیمیشنی که فقط یک‌بار و با `IntersectionObserver` اجرا شود.
6. **لوگوی سازندگان مدل‌ها** — نوار خاکستری‌شده (`opacity:.55`, `filter:grayscale(1)`) از
   لوگوی متنی Anthropic / OpenAI / DeepSeek / Moonshot / Zhipu / MiniMax / xAI؛ روی هاور رنگی شود.
   (لوگوها را به‌صورت وردمارک متنی ساده بساز تا مسئله‌ی حق کپی پیش نیاید.)

**ستون چپ (ویژوال) — این مهم‌ترین بخش گمشده‌ی سایت است:**

یک **ترمینال/ادیتور زنده‌ی شبیه‌سازی‌شده** بساز:
- قاب پنجره با سه نقطه‌ی رنگی، تب‌های `curl` / `python` / `node`.
- کد با هایلایت سینتکس، تایپ‌شونده کاراکتربه‌کاراکتر در لود اول (زیر `reduced-motion` غیرفعال).
- زیرش یک پنل «پاسخ» که بعد از پایان تایپ، استریم‌وار یک جواب فارسی نمایش می‌دهد
  (شبیه‌سازی، بدون تماس واقعی با API).
- دکمه‌ی کپی روی گوشه.
- هاله‌ی `--glow-lg` پشت قاب و یک `border` گرادیانتی ظریف.
- در موبایل: زیر متن قرار بگیرد، ارتفاع ثابت، بدون انیمیشن تایپ.

**جزئیات پیکسلی:**
- `padding-block: clamp(64px, 9vw, 120px)` — نه ۷۰px ثابت.
- فاصله‌ی بین تیتر و زیرعنوان `--sp-5`؛ بین زیرعنوان و CTA `--sp-8`؛ بین CTA و نوار اثبات `--sp-10`.
- محدوده‌ی نور: یک `radial-gradient` بنفش با آلفای ۰.۱۲ پشت گوشه‌ی بالا-راست هیرو.
- ورود بخش‌ها با استگر ۶۰ms (بج → تیتر → زیرعنوان → CTA → آمار → ویژوال).

## بخش ۵ — صفحه اصلی: بخش مدل‌ها

### وضعیت فعلی

`grid-4` با `minmax(220px,1fr)` و **۳۱ کارت یکسان**. هر کارت: `model_id` با رنگ فیروزه‌ای و
وزن ۷۰۰ (چون `provider` خالی است)، `display_name` خاکستری، و یک بج `🟦 ریکوستی` / `🟪 توکنی`.
نتیجه: ۸ ردیف کارت در دسکتاپ که ردیف آخرش ۳ کارت وسط‌چین دارد و ناقص به نظر می‌رسد.
در موبایل: ۳۱ کارت روی هم = چند هزار پیکسل اسکرول.

### طراحی جدید

**۵-۱. هدر بخش**
- تیتر: «مدل‌های پشتیبانی‌شده» + زیرعنوان: «۳۱ مدل فعال از ۷ سازنده — همه با یک کلید».
- سمت مقابل تیتر: لینک «همه‌ی مدل‌ها و وضعیتشان ←» به `/health`.
- استایل `.section-title` فعلی (وسط‌چین با یک کلمه‌ی گرادیانتی) را نگه دار ولی
  به چیدمان چپ/راست‌چین با زیرعنوان ارتقا بده؛ وسط‌چین بودن همه‌ی تیترها یکنواختی می‌سازد.

**۵-۲. کنترل‌ها (بالای گرید)**
- **سگمنتد کنترل**: `همه` / `ریکوستی` / `توکنی` — با `billing_type` فیلتر می‌کند.
  پیل فعال با پس‌زمینه‌ی گرادیانتی و انیمیشن لغزشی (`transform` روی یک `::after` مشترک).
- **چیپ سازنده**: Claude / GPT / DeepSeek / Kimi / GLM / MiniMax / Grok / Qwen — از پیشوند
  `model_id` استخراج شود (چون `provider` از API خالی برمی‌گردد؛ یک `providerOf(model_id)`
  با نگاشت پیشوند بنویس).
- **جست‌وجوی زنده** با آیکن ذره‌بین و دیبانس ۱۵۰ms.
- شمارنده: «۳۱ مدل» که با فیلتر آپدیت می‌شود.

**۵-۳. کارت مدل (بازطراحی کامل)**

هر کارت باید:
- **آیکن/لوگوی سازنده** در گوشه (SVG یا مونوگرام رنگی؛ مثلاً «A» نارنجی برای Anthropic،
  دایره‌ی سبز برای OpenAI) — رنگ لهجه‌ی هر سازنده در `data-provider` ذخیره شود.
- **نام نمایشی** (`display_name`) به‌عنوان تیتر با وزن ۷۰۰، رنگ `--text` — نه `model_id`.
- **`model_id` در فونت مونو، ۱۲px، `--text-faint`، با دکمه‌ی کپی کنارش** (توسعه‌دهنده این را
  می‌خواهد کپی کند؛ الان قابل کپی راحت نیست).
- **بجِ تیر**: `premium` → بج بنفش «پریمیوم» با آیکن نگین؛ `standard` → بج فیروزه‌ای.
  اموجی‌های `🟪🟦` کاملاً حذف شوند.
- **بجِ نوع صورت‌حساب**: «ریکوستی» / «توکنی» به‌صورت چیپ کوچک خط‌دار (outline)، نه پُر.
- **نقطه‌ی وضعیت زنده** از `/api/health/models` (سبز پالسی = فعال).
- **هاور**: `translateY(-3px)`، حاشیه به `--primary` با آلفا، `--glow-sm`، و ظاهر شدن یک
  دکمه‌ی ثانویه‌ی «نمونه کد» که مودالِ اسنیپت آن مدل را باز می‌کند.
- ارتفاع کارت‌ها **باید یکسان باشد** (`grid-auto-rows:1fr`) — الان محتوای متفاوت ارتفاع نابرابر می‌سازد.

**۵-۴. حل مشکل ۳۱ کارت**
- پیش‌فرض فقط **۸ کارت شاخص** نشان بده (مرتب‌شده: premium اول، بعد بر اساس محبوبیت).
- دکمه‌ی «نمایش همه‌ی ۳۱ مدل» که بقیه را با انیمیشن ارتفاع باز می‌کند؛ حالت باز، یک
  **جدول فشرده** باشد (نام | شناسه | سازنده | تیر | نوع | وضعیت) نه کارت — چگالی اطلاعات بالاتر.
- در موبایل: پیش‌فرض ۴ کارت + دکمه‌ی «همه». گرید موبایل ۲ ستونه‌ی فشرده باشد، نه تک‌ستونه.
- حالت لودینگ: ۸ کارت اسکلتون شیمردار.
- حالت خالی: تصویر خالی + متن «مدلی با این فیلتر پیدا نشد» + دکمه‌ی «پاک کردن فیلترها».
- **جلوگیری از دوگانگی:** مدل‌های `t-*` (توکنی) و نسخه‌ی ریکوستی همان مدل نام نمایشی یکسان دارند
  (مثلاً دو کارت «Claude Opus 5»). این‌ها را در یک کارت با دو چیپ نوع صورت‌حساب ادغام کن.

## بخش ۶ — صفحه اصلی: قیمت‌گذاری

### وضعیت فعلی (پرمشکل‌ترین بخش)

- `loadPricing()` پلن‌ها را به دو گروه «رکوستی» و «توکنی» می‌شکند و **دو گرید جدا با دو تیتر بخش**
  می‌سازد → صفحه دو بار بخش قیمت دارد و کاربر گیج می‌شود.
- هر گروه ۴ پلن دارد ولی `grid-3` است → **کارت چهارم تنها در ردیف بعدی یتیم می‌ماند** (بصری فاجعه).
- پلن‌های `test` و `token test` با قیمت **۱ دلار** عمومی نمایش داده می‌شوند.
- بج «پرفروش» به‌خاطر `right:50%` در RTL و متغیر `--secondary` تعریف‌نشده، از گوشه‌ی کارت بیرون می‌زند.
- قیمت `$17` با `font-size:48px` وزن ۹۰۰ رنگ `--text` — بی‌روح و بدون تمایز.
- تبدیل تومان با `tether_rate: 186848` محاسبه می‌شود ولی هیچ‌جا نمی‌گوید نرخ کی آپدیت شده
  (`tether_updated_at` در API هست ولی استفاده نمی‌شود).
- ویژگی‌ها با `::before {content:'✓ '}` سبز — ساده اما بی‌ساختار؛ هیچ تولتیپ توضیحی ندارند.

### طراحی جدید

**۶-۱. ساختار**
- **یک بخش، یک تیتر.** بالای کارت‌ها یک **تاگل سگمنتد**: «پرداخت به‌ازای ریکوست» ↔ «پرداخت به‌ازای توکن»
  با انیمیشن کراس‌فید بین دو مجموعه کارت. زیر تاگل یک خط توضیح تفاوت این دو + آیکن راهنما با تولتیپ.
- گرید را از `auto-fill` به `repeat(3, 1fr)` ثابت تغییر بده (در ≥۱۰۲۴px)، `repeat(2,1fr)`
  در ۶۴۰–۱۰۲۳px و ۱ ستون زیر آن. **هرگز نباید کارت یتیم بماند.**
- پلن‌های تستی: اگر `price < 3` یا نامشان شامل `test` است، در صفحه‌ی عمومی نمایش نده
  (یا یک فلگ `is_public` به API اضافه کن). این‌ها فقط باید در داشبورد دیده شوند.

**۶-۲. کارت قیمت — آناتومی دقیق**

```
┌─────────────────────────────────┐
│      [ بج «پرفروش» — وسط بالا ] │  ← دقیقاً وسط لبه‌ی بالایی، نصفش بیرون کارت
│                                 │
│  نام پلن                    آیکن│  ← 20px/700
│  زیرعنوان (مناسب حرفه‌ای‌ها)      │  ← 14px/--text-muted
│                                 │

│  ≈ ۳٬۱۷۶٬۴۱۶ تومان              │  ← 15px/--text-muted

│  ─────────────────────────────  │
│  ✓ ۱۰۰ میلیون توکن        (i)   │  ← هر آیتم با آیکن SVG چک، نه ::before متنی
│  ✓ دسترسی به همه مدل‌ها     (i)   │
│  ✓ اعتبار ۳۰ روزه          (i)   │
│  ✓ ~۰.۱۷ دلار به ازای ۱M   (i)   │  ← محاسبه‌شده، با تولتیپ فرمول
│                                 │
│  [   خرید اشتراک    ←   ]       │  ← دکمه تمام‌عرض، ارتفاع 48px
```

- **کارت شاخص (`badge` دارد)**: `transform:scale(1.04)` در دسکتاپ، حاشیه‌ی گرادیانتی متحرک
  (کنیک-گرادیانت چرخان با `@property`)، پس‌زمینه‌ی `--elev-2`، `--glow-lg`.
  بج را با `inset-inline-start:50%; transform:translateX(50%)` **و** `top:-12px` درست کن
  (نسخه‌ی فعلی از `right:50%` استفاده می‌کند که در RTL نتیجه‌ی متفاوتی می‌دهد).
- **هاور کارت عادی**: بالا آمدن ۴px + حاشیه‌ی `--primary/40`.
- **نمایش صرفه‌جویی**: اگر پلن گران‌تر قیمت واحد کمتری دارد، یک چیپ سبز «۲۲٪ ارزان‌تر در هر توکن».
- **مقایسه‌گر**: زیر کارت‌ها یک جدول مقایسه‌ی تاشو (`<details>` استایل‌شده) با همه‌ی ویژگی‌ها
  کنار هم؛ در موبایل به‌صورت اسکرول افقی با ستون نام چسبان (`position:sticky`).
- **ماشین‌حساب مصرف** (اختیاری ولی ارزشمند): یک اسلایدر «چند ریکوست/توکن در ماه؟» که پلن
  مناسب را هایلایت می‌کند.
- زیر بخش، ۳ خط اطمینان‌بخش با آیکن: «فعال‌سازی آنی»، «بدون تمدید خودکار»، «پشتیبانی تلگرام ۲۴/۷».

## بخش ۷ — صفحه اصلی: نحوه‌ی استفاده، نمونه کد و بخش‌های جدید

### ۷-۱. «نحوه استفاده» — بازسازی

فعلی: ۴ کارت `grid-4` با اموجی `1️⃣2️⃣3️⃣4️⃣` در ۳۰px، تیتر ۱۶px، متن ۱۳px `--muted`.

جایگزین با **تایم‌لاین افقی** (دسکتاپ) / **عمودی** (موبایل):
- خط رابط گرادیانتی بین مراحل که با اسکرول پر می‌شود (`scroll-driven animation` یا IntersectionObserver).
- هر مرحله: دایره‌ی شماره‌دار ۴۴px با حاشیه‌ی گرادیانتی و عدد **فارسی** (۱،۲،۳،۴) — نه اموجی.
- آیکن SVG برای هر مرحله: ثبت‌نام (کاربر+)، پرداخت (کارت)، کلید (کلید)، اتصال (پریز/براکت).
- متن مرحله‌ها همان فعلی بماند ولی «از طریق درگاه زرین پال پرداخت کن» را با `gates` در API
  همگام کن — الان `zarinpal: false` است ولی متن هنوز زرین‌پال می‌گوید. **این یک تناقض واقعی است.**
  متن را دینامیک کن: کارت‌به‌کارت / کریپتو / زرین‌پال بر اساس `gates`.
- مرحله‌ی ۴ یک لینک «مشاهده‌ی راهنمای اتصال ابزارها» به `/docs` داشته باشد.

### ۷-۲. «اتصال ساده» — بلوک کد

فعلی: دو `.card` کنار هم، هرکدام یک `.code-block` با `Courier New`، رنگ `#9d9dc9`، بدون کپی،
با `<br>` و `&nbsp;` دستی در HTML (نگهداری‌ناپذیر).

جایگزین:
- **یک کارت تمام‌عرض** با **تب‌های زبان**: `cURL` · `Python` · `Node.js` · `Anthropic SDK` ·
  `Claude Code` (تنظیم `ANTHROPIC_BASE_URL`) · `LangChain`.
- هایلایت سینتکس واقعی — یک هایلایتر سبک (مثل Prism با فقط زبان‌های لازم) یا توکنایز دستی.
  رنگ‌ها از پالت: رشته → `--green`، کلیدواژه → `--primary2`، عدد → `--yellow`،
  کامنت → `--text-faint`، تابع → `--cyan`.
- **دکمه‌ی کپی** با فیدبک «کپی شد ✓» و `navigator.clipboard`.
- شماره‌ی خط اختیاری، و **هایلایت خط `base_url`** چون نکته‌ی کلیدی فروش همین است.
- `direction:ltr` روی بلوک کد درست است و باید بماند، ولی اسکرول افقی باید
  `scrollbar-width:thin` و اسکرول‌بار استایل‌شده داشته باشد.
- کنار کد، ستون کوچکی با «نکته»: «فقط `base_url` را عوض کن، بقیه‌ی کدت دست‌نخورده کار می‌کند.»

## بخش ۸ — صفحات احراز هویت (`/login`، `/register`)

### وضعیت فعلی

`.auth-wrap` تمام‌صفحه با یک `.auth-card` (`max-width:420px`, `padding:36px`, `radius:18px`) وسط.
بدون نوبار، بدون فوتر، بدون لینک بازگشت. `.nav-brand` داخل کارت با `justify-content:space-between`
و `width:100%` → لوگو و نام برند به دو سر کارت پرت می‌شوند.
ردیف کپچا (`.captcha-row`) در RTL به‌هم‌ریخته است: باکس سؤال، `input` پاسخ و `🔄` نامرتب.

### طراحی جدید

**چیدمان اسپلیت ۵۰/۵۰ در ≥۹۶۰px:**
- **سمت راست (فرم):** لوگوی کلیک‌پذیر بالای فرم (بازگشت به `/`)، تیتر، فرم، دکمه‌ی تمام‌عرض،
  لینک‌های پایین.
- **سمت چپ (پنل برند):** پس‌زمینه‌ی گرادیانت مش + الگوی گرید، یک نقل‌قول/ارزش‌گزاره،
  و سه نکته با آیکن («۳۱ مدل»، «فعال‌سازی آنی»، «پشتیبانی فارسی»). در موبایل کاملاً حذف شود.

**فرم — جزئیات:**
- ارتفاع فیلد ۴۸px، `--r-md`، پس‌زمینه `--bg2`، حاشیه‌ی `--border`، فوکوس:
  حاشیه‌ی `--primary` + `box-shadow: 0 0 0 3px rgba(99,102,241,.15)` (این حالت فعلی خوب است، نگهش دار).
- **آیکن پیشوند** در هر فیلد (کاربر، ایمیل، قفل).
- **دکمه‌ی نمایش/مخفی رمز** (چشم) — الان وجود ندارد.
- **سنجه‌ی قدرت رمز** در `/register`: نوار ۴ بخشی قرمز→زرد→سبز، زیر فیلد رمز.
- **تطابق آنی دو رمز**: الان فقط موقع submit چک می‌شود و با toast خطا می‌دهد؛ باید
  زیر فیلد دوم به‌صورت زنده تیک/ضربدر بدهد.
- **کپچا را بازطراحی کن:** یک بلوک با لیبل، و ردیفی که در RTL درست بچیند —
  `[سؤال ریاضی] [اینپوت پاسخ] [دکمه‌ی رفرش با آیکن SVG چرخشی]`. باکس سؤال `min-width:96px`،
  وسط‌چین، فونت مونو، رنگ `--primary2` (فعلی خوب است). آیکن رفرش باید `<button>` باشد نه `<span>`،
  با `aria-label`.
- **حالت لودینگ دکمه:** الان `textContent` عوض می‌شود («در حال ساخت...») که باعث پرش عرض دکمه
  می‌شود. به‌جایش اسپینر داخل دکمه با عرض ثابت.
- **خطاها:** به‌جای فقط toast، خطای فیلد-به-فیلد زیر همان فیلد + `aria-live="polite"`.
- **مودال «بازیابی رمز عبور»** در `/login` (الان `h3` دارد) را به همان استایل مودال جدید ببر.
- **`autocomplete`** ها فعلاً درست هستند (`username`, `new-password`) — حفظشان کن.
- `/register` باید یک چک‌باکس «قوانین را می‌پذیرم» با لینک داشته باشد.

- **کلیدهای API**: کلید ماسک‌شده (`sk-sinox-••••••1234`)، دکمه‌ی نمایش/کپی/ابطال، تاریخ آخرین استفاده،

### ۱۰-۲. ریسپانسیو — نقاط شکست دقیق

| بریک‌پوینت | رفتار |
|-----------|-------|
| `< 480px` | تک‌ستونی، `--sp` ها یک پله کمتر، هیرو بدون ویژوال انیمیشنی، گرید مدل ۲ ستونه‌ی فشرده |
| `480–767px` | گرید ۲ ستونه، قیمت تک‌ستونی، درور ناوبری |
| `768–1023px` | گرید ۲–۳ ستونه، سایدبار داشبورد جمع‌شده، هیرو تک‌ستونی وسط‌چین |
| `1024–1279px` | چیدمان کامل، هیرو دو ستونی، داکس دو ستونی |
| `≥ 1280px` | کانتینر ۱۲۰۰px، داکس سه ستونی، قیمت ۳ ستونه |

- بریک‌پوینت‌های فعلی نامنظم‌اند (`560`, `640`, `768`) — یکدستشان کن.
- `.main-content { margin-right: 240px }` را با CSS Grid جایگزین کن تا در حالت جمع‌شده‌ی
  سایدبار نیازی به هماهنگ‌سازی دستی عدد نباشد.
- **سقف ارتفاع صفحه در موبایل**: صفحه‌ی اصلی نباید بیش از ~۶۰۰۰px باشد (الان ۱۰۸۱۵px است).
- تست در ۳۶۰×۶۴۰، ۳۹۰×۸۴۴، ۴۳۰×۹۳۲، ۷۶۸×۱۰۲۴، ۱۲۸۰×۸۰۰، ۱۴۴۰×۹۰۰، ۱۹۲۰×۱۰۸۰.
- ناحیه‌ی لمسی حداقل ۴۴×۴۴px برای هر عنصر تعاملی.

### ۱۰-۳. دسترس‌پذیری (اجباری)

- کنتراست AA: `--muted` را به `#9c9cba` ببر؛ متن فوتر `#4a4a6a` را جایگزین کن.
- `:focus-visible` روی همه‌چیز: `outline: 2px solid var(--primary); outline-offset: 2px`.
  (الان هیچ استایل فوکوسی وجود ندارد.)
- ترتیب تب منطقی؛ `skip to content` مخفی در ابتدای صفحه.
- هر آیکن تنها با `aria-label`؛ هر تصویر با `alt`؛ هر بخش با `<section aria-labelledby>`.
- `role="status"` + `aria-live` برای toast و محتوای async.
- `prefers-reduced-motion: reduce` → همه‌ی ترنزیشن‌ها به `0.01ms`، تایپ‌رایتر و پارالاکس خاموش.
- ناوبری کامل با کیبورد در درور، مودال، دراپ‌داون، تب‌ها و آکاردئون.
- `lang="fa" dir="rtl"` حفظ شود؛ بلوک‌های کد `dir="ltr"` بمانند.
- استفاده از `inset-inline-start/end` و `margin-inline` به‌جای `left/right` در همه‌ی CSS جدید
  (کد فعلی مخلوط است و همین باعث باگ بج «پرفروش» شده).

### ۱۰-۴. پرفورمنس

- فونت وزیرمتن **لوکال** با `woff2` + `preload` + `font-display:swap` + زیرمجموعه‌ی فارسی/لاتین.
- CSS را به `critical` (اینلاین در `<head>`) و بقیه تقسیم کن؛ `style.css` فعلی روی همه‌ی
  صفحات کامل لود می‌شود (شامل استایل داشبورد و ادمین که در صفحه‌ی اصلی لازم نیست).
- `content-visibility: auto` روی بخش‌های پایین صفحه.
- تصاویر: `loading="lazy"` + `decoding="async"` + ابعاد صریح برای جلوگیری از CLS.
- انیمیشن فقط با `transform` و `opacity` (بدون انیمیت `width/height/top`).
- اهداف: LCP < ۲.۵s، CLS < ۰.۱، TBT < ۲۰۰ms، لایت‌هاوس موبایل ≥ ۹۰ در هر چهار محور.

### ۱۰-۵. SEO و متا (الان تقریباً هیچ چیزی وجود ندارد)

- `<meta name="description">` فارسی برای هر صفحه (هیچ صفحه‌ای الان ندارد).
- Open Graph + Twitter Card + تصویر OG اختصاصی ۱۲۰۰×۶۳۰.
- `<link rel="canonical">`، `robots.txt`، `sitemap.xml`.
- JSON-LD: `Organization`، `Product` + `Offer` برای هر پلن، `FAQPage`، `BreadcrumbList`.
- فاوآیکن کامل (SVG + ICO + apple-touch-icon) و `manifest.json` — الان هیچ فاوآیکنی نیست.
- `<title>` های یکتا و توصیفی برای هر صفحه.

### ۱۰-۶. تعریف «تمام‌شده» (چک‌لیست تحویل)

کار وقتی تمام است که همه‌ی این‌ها درست باشند:

- [ ] هیچ اموجی‌ای به‌عنوان آیکن در UI باقی نمانده (در متن محتوا اشکالی ندارد).
- [ ] هر ۱۰ باگ فهرست‌شده در بخش ۱-۱ رفع شده و با اسکرین‌شات قبل/بعد اثبات شده.
- [ ] `--surface` / `--secondary` / `--error` تعریف شده‌اند و هیچ `var()` تعریف‌نشده‌ای نمانده.
- [ ] هیچ کارت یتیمی در هیچ گریدی، در هیچ بریک‌پوینتی وجود ندارد.
- [ ] پلن‌های تستی از صفحه‌ی عمومی حذف شده‌اند.
- [ ] متن درگاه پرداخت با `gates` در `/api/plans` همگام است (زرین‌پال الان `false` است).
- [ ] هر محتوای async حالت لودینگ (اسکلتون)، خطا و خالی دارد.
- [ ] ارتفاع صفحه‌ی اصلی در موبایل زیر ۶۰۰۰px است.
- [ ] لایت‌هاوس موبایل ≥ ۹۰ در Performance / Accessibility / Best Practices / SEO.
- [ ] کنتراست همه‌ی متن‌ها از AA عبور می‌کند (با ابزار بررسی شود، نه با چشم).
- [ ] هر مسیر تعاملی فقط با کیبورد قابل طی است.
- [ ] پالت رنگی اصلی دقیقاً همان مقادیر هگز بخش ۲-۱ است.
- [ ] هیچ تغییری در قرارداد API داده نشده.

### ۱۰-۷. ترتیب اجرا

۱. سیستم طراحی + رفع باگ‌های CSS (بخش ۲) — پایه‌ی همه‌چیز، اول این.
۲. هدر/فوتر (بخش ۳) — در همه‌ی صفحات مشترک است.
۳. صفحه‌ی اصلی: هیرو → مدل‌ها → قیمت → کد → بخش‌های جدید (بخش‌های ۴ تا ۷).
۴. احراز هویت (بخش ۸) — کوچک و پربازده.
۵. داکس / مقالات / هلث (بخش ۹).
۶. داشبورد (بخش ۱۰-۱).
۷. پولیش: دسترس‌پذیری، پرفورمنس، SEO (بخش‌های ۱۰-۳ تا ۱۰-۵).
